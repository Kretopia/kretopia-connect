# New Room — Release Gate

Companion to `NEW_ROOM_UX_AUDIT.md`. This is the single source of truth for what shipped in this pass vs. what's flagged for later — the other report files below cover their own areas in more depth, but check here first for the overall status.

## What this pass was

Not a rebuild. The audit found New Room already had a real, working 4-mode voice-first intake flow (`VoiceFirstCreateModal.tsx` + `StudioCreateHero.tsx`, backed by the real `extract-brief` edge function). This pass fixed the concrete gaps the audit surfaced, in priority order, rather than reskinning what already worked.

## Implemented, typechecked, tested, and browser-verified

- **Persona/`WorkspaceType` mismatch (P0)** — `supabase/functions/extract-brief/index.ts`'s persona map was keyed on a 7-value vocabulary that didn't match any of the app's real 11 `WorkspaceType` values except `general`; every real project type silently got the generic fallback persona. Rewrote the map to the real enum: `photo_shoot`, `fashion_show`, `commissioned_art`, `dj_live_gig`, and `edit_job` got new tailored personas; `event_production`, `music_project`, `brand_collab`, and `content_series` reused and adapted the existing `event`/`music`/`campaign`/`podcast` personas onto their correct real keys. Verified live: submitted "Editorial fashion runway show with 8 models, backstage roll call at 6pm" and got back genuinely fashion-show-specific deliverables ("Venue, Team & Model Casting Confirmation," "Styling & Rehearsal Execution," "Live Show & Content Capture") instead of the old generic fallback.
- **Three real classification bugs in `inferWorkspaceType`** — found while writing its first test suite, not hypothetical: "lineup" and "mix" were generic keywords checked before the more specific "model lineup"/"audio mix" phrases that should have won, and "lookbook" was claimed by `fashion_show` despite `workspaceConfigs.ts`'s own description listing lookbooks under `photo_shoot`. Fixed all three; extracted the function to `src/lib/inferWorkspaceType.ts` so it's independently testable (previously inline and unexported inside the 1200-line modal component).
- **Accessibility (P0)** — the modal is a hand-rolled overlay, not a Radix `Dialog`, so focus trap, focus return, and `aria-labelledby` didn't come for free and were missing. Added a manual Tab-trap, focus-return-to-trigger on close, and `aria-labelledby` pointing at the real visible "New Room" label (was a duplicated static `aria-label` string before). Verified live: Shift+Tab from the first focusable element (Close) wrapped to the last one inside the dialog rather than escaping to the page; Escape closed the modal and returned focus to the "Open a New Room" button.
- **Hardcoded colors** — `const ACCENT = "#FF2DA1"` and ~20 raw `rgba(255,45,161,…)` strings across both files replaced with `hsl(var(--energy))`-based values (and one `#05070D` background with `hsl(var(--background))`), so the feature actually tracks the app's real design token instead of a hardcoded hex that happened to match it. Verified live — colors render identically to before (expected, since the values are the same; the fix is architectural, not visual).
- **`new_room_*` analytics** — added 11 event methods to `src/lib/analytics.ts` (opened, input-mode-selected, voice started/completed, text submitted, file uploaded, link submitted, draft ready, draft cancelled, project confirmed, creation failed) plus a `featureUsed` call for starter-intent selection, instrumented at the real state-transition points already present in the code. No raw transcripts/file contents/brief text logged — metadata only (mode, workspace type, duration bucket, file type, error category), per the audit's own safe-logging requirement.
- **Dead code removed** — `CreateProjectWizard.tsx`, `CreateProjectDialog.tsx` (its only mount point, unreferenced anywhere else), and `workspaceRecommendations.ts` (only ever consumed by the wizard) — a second, fully unreachable "create project" flow that duplicated the real one and would have confused anyone reading the codebase.
- **Draft-then-confirm trust model** — verified live, not just read: submitting a real brief produces a full review screen (editable title, vision, starter tasks) with **no** network write to `projects` until an explicit Create click; clicking "Start over" clears the draft (confirmed via `clearDraft()`) without creating anything.
- **Duplicate-project race (P0)** — the only guard against a double-click/double-tap creating two projects was the `creating` React state boolean, which lags a render behind the click handler and can't fully close a fast-enough race. Added a synchronous `creatingRef` guard checked and set before any async work in `createProject()`. Verified by a dedicated test that drives the full flow (starter intent → text submit → review → answer the required "Money involved?" gate → double-click Create) and asserts the `projects` insert fires exactly once.
- **Responsive matrix** — all 7 required breakpoints (375×667, 390×844, 430×932, 768×1024, 1024×768, 1280×800, 1440×900) checked live: zero horizontal overflow at any of them (`document.body.scrollWidth === window.innerWidth` at each), starter-intent grid correctly reflows 2/3-column by width, content stays sensibly max-width'd rather than stretching edge-to-edge at 1440px.
- **Reduced motion** — verified via full code-path audit rather than live OS-level toggling (no direct `prefers-reduced-motion` emulation control in the available browser tooling): every framer-motion entry/exit/loop in both files is gated on the shared `reducedMotion` variable (7 gated call sites, listed in `NEW_ROOM_ACCESSIBILITY_REPORT.md`), and the one plain-CSS animation not individually gated (the mic button's `animate-ping` halo) is covered by the app's existing global `@media (prefers-reduced-motion: reduce) { *, *::before, *::after { animation-duration: 0.01ms !important; ... } }` rule in `src/index.css` -- confirmed present and unconditional, not something this pass added.

## Explicitly out of scope this pass (documented, not silently dropped)

- **Converting the overlay to a real Radix `Dialog`** — the established app convention, and the right long-term architectural fix, but a full re-platform of a 1200-line 4-mode stateful component is a separate, larger undertaking than the surgical accessibility patch applied here. The current fix closes the actual behavioral gaps (trap/return/label) without that risk; deferred as a real P2 recommendation, not a blocker.
- **True server-side idempotency** (a client-generated key checked against a unique DB constraint) for the network-retry case specifically -- as opposed to the double-click case, which is now closed (see above). A retry after a genuinely lost response (the original request succeeded server-side but the client never saw it) is the one remaining path to a duplicate project, and closing it needs a migration, which this pass does not apply per the standing rule against unprompted migrations. Judged acceptable to ship past given how narrow the residual case is (requires a lost response *and* a manual retry) once the dominant double-click case is closed.
- **Voice-specific and file-upload-specific automated test coverage** — real `MediaRecorder`/`getUserMedia` and `pdfjs-dist`'s `DOMMatrix` dependency aren't available in jsdom; these paths were verified by reading the code and by the live browser pass covering the accessibility/text-input/draft/cancel flow, not by automated tests.
